# 报白接口与验证

更新：2026-11-13（America/Los_Angeles）。依据当前实现记录，未增加产品规则。

## 当前规则

- 剧场名额：年 200、月 100；待审核和已通过占用，已驳回不占用。按申请 created_at 和服务器本地当前年月统计。
- 每视频号最多占用 2 个剧场（不计已驳回）。同视频号同剧场已存在申请时仍拒绝重复申请，包括已驳回记录；如需允许重申，须先确认需求。
- 剧场剩余名额由实时查询计算，旧 theaters.quota_left 字段不是当前计算依据。

## 审核

`PATCH /api/admin/applications/{id}`，需要管理员登录 Cookie；请求体 `{"status":"已通过"}` 或 `{"status":"已驳回"}`。

成功 200：`{"ok":true}`。非法状态或已处理 400，申请不存在 404，数据库操作失败 500（`{"error":"审核失败"}`）。鉴权层未登录 401 / 无管理员权限 403 沿用原实现。

仅待审核申请可处理。状态、reviewed_at 与用户通知在一个 SQLite 事务中提交；任一步失败回滚，避免返回成功却丢失通知。条件更新防止重复处理。本进程沿用单连接数据库池，并发审核回归确认只有一次成功和一条通知。

## 验证

`api_test.go` 使用独立内存库，无种子业务数据。包含审核成功/回滚/并发/校验，以及名额边界和释放测试。Go 源码修改后执行 gofmt，再执行：

```sh
go test -race ./...
go vet ./...
go build -o /tmp/tomato-site-check .
```

本次额外用编译产物在本机随机端口及临时数据库运行 HTTP 注册→申请→管理员驳回→名额恢复→通知流程，通过。临时脚本和构建产物不纳入源码交付。

## 验证边界

未做生产写入、发布、真实手机浏览器验收或远程 PR review。新申请的并发名额竞争尚待后续修复；本轮事务覆盖审核，不代表提交链路已具备原子性。
